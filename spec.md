# Локализация Explorer: русский, английский, испанский

## 1. Цель

Добавить полноценный выбор языка интерфейса для личной и GitHub-сборки Explorer,
сохранив работу файловых операций, клавиатуры, окон и пользовательских настроек.

## 2. Требования

1. Поддержать `ru`, `en`, `es`: русский, английский и испанский.
2. По умолчанию использовать режим «Как в системе». Выбирать первый поддерживаемый
   язык из упорядоченного списка предпочтительных языков macOS; региональные
   варианты (`ru-RU`, `en-GB`, `es-MX` и т. п.) сопоставлять с базовым языком.
   Если поддерживаемых языков в списке нет, использовать английский.
3. Добавить отдельное стандартное окно Settings с выбором языка:
   «Как в системе», «Русский», «English», «Español». Названия языков показывать
   на самих языках, чтобы пользователь мог исправить ошибочный выбор.
4. Сохранять выбор между запусками. Возврат к системному режиму удаляет собственное
   переопределение языка приложения, не меняя настройки macOS или других программ.
5. Применять смену языка со следующего запуска. Показывать это объяснение и статус
   необходимости перезапуска; не закрывать приложение автоматически и не терять
   текущее выделение, вкладки, адрес или незавершённое переименование.
6. Локализовать команды и контекстные меню, подписи и подсказки панели,
   настройки, встроенные разделы боковой панели, заголовки таблицы, фильтр,
   пустые состояния, счётчики, Get Info и сообщения об ошибках, создаваемые Explorer.
   Стандартные меню AppKit должны использовать выбранный язык при запуске.
7. Поддержать формы множественного числа для количества объектов и выделения,
   включая русские формы для 1, 2–4, 5–20 и составных чисел.
8. Отображать даты и размеры с учётом языка/локали интерфейса.
9. Не переводить существующие имена файлов, пути, имена приложений, пользовательские
   теги и названия пользовательских избранных папок. Для точных стандартных путей
   Home/Desktop/Documents/Downloads переводить встроенные подписи, в том числе
   после загрузки сохранённого избранного. Локализованные названия стандартных цветов
   тегов не должны менять сохранённые значения Finder. Новая папка может получать
   локализованное исходное имя; конфликтные суффиксы должны продолжать работать.
10. Системные сообщения ошибок и описания типов файлов предоставляет macOS;
    собственные пояснения Explorer должны быть переведены. Нельзя обещать перевод
    произвольного текста сторонних приложений или файлов.
11. Все три набора ресурсов должны входить в SwiftPM-сборку, `.app`, ZIP и
    универсальную сборку GitHub Actions. Минимальная версия macOS остаётся 14.

## 3. Реализация

- Использовать стандартные `.lproj/Localizable.strings` и ресурсы множественного числа.
- Ввести единый `L10n` для SwiftUI и AppKit, строк с параметрами и фоновых сервисов.
  Пропущенный перевод должен иметь безопасный английский резервный вариант.
- Отделить сохранённый выбор языка от активного языка текущего процесса.
- Согласовать собственный выбор с per-app `AppleLanguages`, чтобы системные меню
  использовали тот же язык после перезапуска. Системный список читать независимо
  от этого переопределения. Не менять глобальный домен настроек.
- Объявить доступные локализации и язык разработки в метаданных пакета и приложения;
  копировать ресурсный bundle SwiftPM внутрь готового приложения.
- Не повышать версию и не публиковать новый релиз автоматически в рамках этой задачи.

## 5. Критерии приёмки

1. Чистый профиль автоматически выбирает поддерживаемый язык системы.
2. Каждая ручная настройка сохраняется; после перезапуска интерфейс использует её.
3. Возврат к системному режиму снова учитывает системные предпочтения.
4. Ошибочное сохранённое значение не мешает запуску и обрабатывается как системный режим.
5. Для всех языков есть одинаковый набор ключей и совместимые параметры формата.
6. Числа 0, 1, 2, 5, 11, 21 и 22 отображаются с правильными формами.
7. Смена настройки не изменяет файловые данные и состояние открытого окна до перезапуска.
8. Готовое приложение запускается и находит переводы без исходников и каталога сборки.
9. Прежние регрессионные тесты проходят; новые тесты не меняют реальные предпочтения
   пользователя, используя отдельные домены UserDefaults.

## 6. Результаты

Реализация завершена 7 ноября 2026 года.

- Добавлены 83 строковых ключа и 2 ключа множественного числа на каждый язык.
- Полный прогон: **61 тест в 13 наборах**, все прошли. Прежние регрессионные
  сценарии сохранены; зависящие от английского проверки адаптированы к локали.
- Проверены точные формы чисел 0, 1, 2, 5, 11, 21, 22, совместимость параметров
  формата, корректность сохранения/удаления настройки и неизвестные значения.
- В отдельном приложении с собственным bundle ID кликами проверена цепочка:
  системный русский → Español → English → системный русский. На каждом запуске
  подтверждены язык интерфейса и стандартных меню macOS; выбор сохранялся.
- Окно настроек показывает все четыре варианта и предупреждение о перезапуске;
  русский, английский и испанский текст помещается в окне. До перезапуска
  сохраняется прежний язык текущего интерфейса.
- В отдельной проверке подтверждены локализованные имена новых папок, формат
  размеров и подписи встроенных избранных папок после восстановления настроек.
  Пользовательская папка с именем Desktop в другом месте не переименовывается.
- Debug `.app` и универсальная release-сборка arm64 + x86_64 собраны успешно.
  Подпись `.app`, целостность ZIP и наличие всех шести таблиц ресурсов проверены.
  Загрузка ресурса из Contents/Resources проверена отдельно от каталога сборки.
- `git diff --check` прошёл. README и инструкции для разработчика обновлены.

### Границы проверки и поставки

- Интерфейс проверен на Apple Silicon; Intel-часть собрана и проверена как Mach-O,
  отдельный запуск на Intel не выполнялся.
- Для этой доработки GitHub Actions не запускался: изменения ещё не закоммичены
  и не отправлены. Существующий workflow использует обновлённый общий скрипт,
  которым локально проверена универсальная упаковка.
- Версия и опубликованный релиз не менялись. Архив в локальном dist — проверочная
  сборка текущего исходного кода, а не новый опубликованный выпуск.
- Рабочее приложение в ~/Applications и его языковые настройки не изменялись;
  UI-проверка выполнялась на отдельной тестовой копии.
- Текст, который предоставляет macOS или сторонние приложения, остаётся в ведении
  соответствующего поставщика; например, стороннее описание типа файла может
  оставаться на английском даже в русском интерфейсе.
